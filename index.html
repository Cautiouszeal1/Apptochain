1. The problem

On-chain activity never pauses, but people do. Funds move at 4 a.m., approvals get signed by mistake, LP positions drift out of range, vesting cliffs pass unnoticed. Existing tools either demand engineering effort (custom bots, node infrastructure) or offer generic notifications with no logic behind them. The gap: programmable vigilance without programming.

2. The agent model

An AppToChain agent is a rule set bound to an on-chain target. Rules combine live metrics — native balance, token balance, balance delta, market price, gas — with comparison operators under AND/OR logic. When rules fire, the agent transitions to an alert state and dispatches through every configured channel: Telegram, webhook, desktop push. Quiet hours suppress noise without pausing evaluation.

Five agent archetypes ship at launch: Wallet Monitor, Suspicious Activity, Trade Executor, Treasury Guardian, and Position Monitor. All share the same rule engine, so improvements compound across every agent type.

3. Architecture

Phase one runs client-side: direct RPC reads against BNB Smart Chain (balance, gas, eth_call for BEP-20 state) with market data from public price APIs. Phase two moves evaluation to a persistent worker layer, so agents run whether or not a browser is open, with transaction-level indexing for approval and contract-interaction detection. Phase three introduces delegated execution: session-scoped signing keys with hard caps, enabling Trade Executor and Treasury Guardian to act, not just alert. Custody for treasury operations is designed around Gnosis Safe rather than platform-held keys.

4. $APTC token

$APTC is the platform's metering and governance asset on BNB Smart Chain. Total supply is fixed at 1,000,000,000. Agent execution beyond the free tier, elevated polling frequency, and priority alert routing are paid in $APTC. Staking unlocks capacity tiers. A portion of platform fees funds quarterly buy-back-and-burn. Governance weight is proportional to staked balance, voting on new agent archetypes, supported chains, and fee parameters. Allocation: 30% community & rewards, 20% liquidity, 15% team (24-month linear vest, 6-month cliff), 15% ecosystem treasury, 10% public sale, 5% partners & advisors, 5% reserve.

5. Security model

The platform is non-custodial by default: monitoring requires only public addresses, never keys. Wallet connection is used for identity and convenience, not custody. When delegated execution ships, it will use scoped session keys with per-transaction and aggregate caps, revocable at any time, and treasury actions will always settle through user-owned multisigs. Account security includes TOTP two-factor authentication and per-user session logs with device and location visibility.

Q1 2027 — delegated execution for Trade Executor, Gnosis Safe treasury integration. Q2 2027 — Solana support, agent marketplace where builders publish rule templates and earn $APTC on installs.
